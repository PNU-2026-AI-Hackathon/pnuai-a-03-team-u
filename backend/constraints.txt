# 의존성 버전 잠금 (보안 계획 P1-3).
#
# requirements.txt는 "무엇에 직접 의존하는가"만 적고, 실제 버전은 여기서 잠근다.
# 설치는 항상 두 파일을 같이 쓴다:
#
#     pip install -r requirements.txt -c constraints.txt
#
# 이 파일이 없으면 매번 최신 버전이 깔린다. 실제로 2026-08-15 시점에 핀 없이 새로
# 설치하면 openai 2.44 → 3.1(메이저), cryptography 49 → 50, wrapt 1.17 → 2.3,
# langchain-core 1.4.8 → 1.5.5가 깔렸다. 즉 주간 golden-eval CI가 로컬에서 검증한
# 것과 다른 스택 위에서 돌고 있었다. LLM 회귀를 감시하는 CI가 정작 라이브러리
# 버전 때문에 흔들리면 감시 자체가 무의미하다.
#
# ── 버전 선정 기준 ────────────────────────────────────────────────────────
# "오늘 최신"이 아니라 **챗 골든 스윕 72/78(92%)을 실제로 낸 개발 환경의 버전**을
# 그대로 고정했다. 검증된 적 없는 최신으로 올리는 건 별도 작업으로 분리한다.
#
# ── 재생성 방법 ───────────────────────────────────────────────────────────
# 직접 의존성을 requirements.txt에 추가/변경한 뒤, CI와 같은 Python으로:
#
#     python3.12 -m venv /tmp/lockenv
#     /tmp/lockenv/bin/pip install -r backend/requirements.txt
#     /tmp/lockenv/bin/pip freeze > backend/constraints.txt
#
# 그리고 이 헤더를 다시 붙인다. 깨끗한 venv에서 만들어야 개발 머신에만 있는
# 잡다한 패키지(pandas, openpyxl, pyhwp 등)가 섞이지 않는다.
#
# ── 검증 ──────────────────────────────────────────────────────────────────
# 이 집합은 Python 3.12(= CI 버전)에서 설치 성공을 확인했다. 개발 venv는 3.14지만
# 같은 버전 조합이 3.12에서도 해석된다. 113개 패키지 = requirements.txt의 전이 폐포.
#
# ── 주의 ──────────────────────────────────────────────────────────────────
# constraints는 "설치하라"가 아니라 "설치한다면 이 버전으로"다. 여기 없는 패키지는
# 자유롭게 깔리므로, 새 직접 의존성은 requirements.txt에 추가하고 이 파일을 재생성해야
# 잠긴다. pytest처럼 CI에서만 쓰는 것도 아래에 없으면 안 잠긴다.
